# AI Native 工程规范：目标与交付物

状态：已冻结（v1.6）｜日期：2026-11-25

## 1. 目标

**用户在新项目目录中向 Codex 发送一句提示词，即可创建一套从需求到交付的项目资料目录。打开项目根目录的 `README.md`，用户就能知道每个目录做什么、什么时候用，以及该把什么放进去。**

首次使用提示词（冻结原文）：

> 请读取 https://github.com/soyona/ai-native-engineering-kit 的 README，按照其中的初始化指南，在当前目录初始化我的新项目。

规范仓库的 README 提供初始化指南；用户项目根目录的 README 提供目录使用指南。空目录即可初始化，无需先提供需求或选定技术栈；已有资料时，保留原文件与位置，不移动、不覆盖。

## 2. 初始化交付物

1. **实际创建的项目目录。** 在用户项目中创建第 3 节的七类目录；已有同名目录直接复用。目录可以为空，无需同时生成阶段文档。
2. **一份目录使用指南。** 在项目根 `README.md` 中按「目录｜什么时候用｜典型内容」说明每个目录。已有 README 时保留原文并补充目录指南；已有相同说明时不重复添加。无需为每个目录另写 README。

## 3. 目录及用途

以下路径相对于用户项目根目录。

| 目录 | 什么时候用 | 典型内容 |
| --- | --- | --- |
| `docs/inputs/` | 收到尚未整理的原始资料时 | 访谈原稿、客户来稿、调研材料；已有原件可以留在原处。 |
| `docs/requirements/` | 说明要解决什么问题、功能怎样才算满足需求时 | 项目范围、PRD、功能规格、验收条件。 |
| `docs/design/product/` | 设计用户如何完成任务时 | 用户流程、页面原型、交互与异常状态说明。 |
| `docs/design/technical/` | 决定功能如何实现时 | 架构设计、模块职责、接口契约、数据模型。 |
| `docs/development/` | 安排和记录开发工作时 | 实施计划、任务拆解、关联变更记录；不存放业务源码。 |
| `docs/verification/` | 核对需求是否满足时 | 测试用例、测试结果、业务验收记录。 |
| `docs/delivery/` | 向使用方交付版本时 | 版本说明、使用手册、部署与交接记录。 |

## 4. 完成标准与边界

- **目录存在：** 在空项目中发送冻结提示词后，七类目录均实际存在。
- **说明可用：** 根 README 所列路径与实际目录一致。首次使用者能仅凭指南判断：访谈原稿放在哪里、整理后的需求放在哪里、测试结果放在哪里。
- **原件保留：** 在已有资料的项目中初始化，原件不被移动或覆盖；重复初始化不重复添加指南。

技术选型、代码骨架、CI 配置、运行测试、多智能体协作和各阶段业务文档的编写均不属于初始化交付物。从需求到交付界定的是目录覆盖范围，不要求用户在初始化时完成任何研发阶段。

当前仅维护本目标文档，不在规范工作区创建上述目录或 README。
