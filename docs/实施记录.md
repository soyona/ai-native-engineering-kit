# 项目目录初始化：方案、实施与验收

依据：《目标与交付物》v1.6。方案 R3 已于 2026-11-25 经两名独立 AI 终审通过并冻结。目标项目只收到目录和根 README，不包含本记录。

## 方案 R3

1. 交付一个自含的规范仓库 README：首屏给出冻结的单句，后接 Codex 可直接执行的初始化指南和七行目录用途表。用户无需安装脚本、选择语言或提供业务资料。不可读取来源时如实停止。
2. 当前用户项目为唯一写入根。写前检查七个路径、父目录和 README：普通目录复用；目录名被普通文件占用、README 类型不符、目标链含符号链接或重解析点时停止，说明路径，预检失败零写入。既有原件不移动、不读取业务内容、不上传。
3. 七个叶目录实际建在磁盘上，无占位文件。根 README 不存在时新建；存在时保留原文字节，按路径判断已有说明是否同时回答“何时用、放什么”，仅补缺失项或字段，等价表述有效。完全覆盖时不写。保留原编码、BOM 和换行；无法可靠识别或遇到互相矛盾的说明时先确认。
4. 分别报告目录是否建齐、指南是否覆盖和实际变更；不以目录存在代替指南核验。非预检的意外失败报告已经发生的变更，不删除用户资料。重复执行不改变项目内容。
5. 两层验收：本地候选版实物演练；正式入口由无历史会话在独立项目中只收到冻结单句，经实际 GitHub 来源执行。已有材料场景对比原件路径与字节、README 前缀及重复运行哈希；冲突要求前后无变化。首次读者只看结果 README 回答三道归档题。匿名访问与已授权仓库访问分别报告，AI 演练不代替人类签认。
6. 发布前的本地验收分给两个互不共享历史的新代理：A 在空项目中按候选指南初始化，B 只读取该项目生成的 README，回答访谈原稿、已整理需求和测试结果各放哪里；验收者将答案逐项与实物路径比对。GitHub 单句验收独立进行。
7. 仅在需补写已有 README 时，写入前确认硬链接数为 1；多于 1 或无法确认时停止。用一个链接到项目外原件的 README 复核：不新增目录，两边内容及路径均不变。

## 初审处置

| 初审 | 发现 | R1 处置 |
| --- | --- | --- |
| A：面向用户 | 本地与 GitHub 不可混报、需要盲读指南、重复与冲突要比对实物 | 纳入第 3—5 条 |
| B：资料完整性 | 预检父路径和 README、逐项语义去重、正式入口需实跑 | 纳入第 2—5 条 |

终审修订：R1 缺本地双代理盲验，R2 缺硬链接写入预检；R3 补齐两项后，A、B 均确认无剩余方案阻断。此结论不代表实物验收通过。

## 冻结后的实施计划

| 顺序 | 工作 | 退出条件 |
| --- | --- | --- |
| 1 | 实现规范仓库 README；核对冻结原句、七行用途及范围 | 用户只需发送提示词，指南无需额外安装即可执行 |
| 2 | 在独立临时目录准备空项目、已有资料、路径冲突和硬链接样例 | 实际创建结果可核查；已有材料按路径与字节比对 |
| 3 | 独立盲读、重复执行、检查指南及边界案例 | 三道归档题与实际目录一致；已完成项目再运行无变化；冲突不写入 |
| 4 | 将已验证的入口发布到指定 GitHub 仓库，另开新会话只发送冻结提示词 | 核对远端提交与从入口生成的项目；无法访问时区分权限与功能结果 |

## 实物验收（2026-11-25）

| 用户场景 | 实测结果 |
| --- | --- |
| 空项目，依据本地候选指南初始化 | 七个叶目录全部存在，根 README 每项说明出现一次，无额外文件。冻结提示词、七个规范路径与目标文档逐项核对一致。 |
| 已有部分说明及原始材料 | 复用既有 inputs 目录及自然语言说明，仅追加六项；原 README 字节前缀、UTF-8 BOM、CRLF 均保留。原始资料位置和 SHA-256 不变。 |
| 同项目再次初始化 | 七个目录复用，README 不重复追加；两次运行后的 README SHA-256 均为 `E7FAD9B6C85ED6FE4256EE57E8F4AF56B35D68E57507900E591D650F61B8CE34`。 |
| 路径被普通文件占用；README 与外部原件互为硬链接 | 两个独立样例均在预检停止，未新建目录；前后路径和文件哈希一致。 |
| 独立首次读者仅阅读生成的 README | 访谈原稿 → `docs/inputs/`；整理后的需求 → `docs/requirements/`；测试结果 → `docs/verification/`。3/3 与磁盘目录一致。 |

以上为本地设备上的独立 Codex 用户场景验收，未据此认定 GitHub 入口可用；未安排真人业务签认。
