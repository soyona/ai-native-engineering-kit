# AI Native 工程规范

在 Codex 中打开新项目文件夹，发送这一句话：

```text
请读取 https://github.com/soyona/ai-native-engineering-kit 的 README，按照其中的初始化指南，在当前目录初始化我的新项目。
```

完成后会得到七个资料目录和一份使用指南。打开**自己项目根目录的 `README.md`**，就能判断一份资料该放在哪里。空文件夹或已有资料的项目都适用，不用准备需求、安装工具或选定技术栈。

## 初始化指南（给 Codex）

1. **确认位置，先检查后写入。** 唯一写入位置是用户打开的目标项目，规范仓库只供读取。检查下表七个路径、它们的父目录以及根 `README.md`。已有普通目录复用；若目录路径被文件占用、README 不是普通文件，或上述路径含符号链接、目录联接等重解析点，直接报告具体位置并停止，不创建任何目录。若无法取得或确认指南来源，停止，不自行猜测。
2. **先确定 README 需要补什么。** 只需查看目标路径及根 README，无需读取、整理、移动或上传已有业务资料。按目录路径逐项判断原说明是否已表达“什么时候用”和“放什么”，不同标题、列表或同义表述均有效。已有七项完整说明则不写；缺项只补缺项，单项缺字段只补该字段。有冲突的说明先询问，不自行改写。补写前确认原编码与换行、文件硬链接数为 1；无法确认或硬链接数大于 1 时，停止并说明原因。Windows 可用 `fsutil hardlink list` 枚举现有名称，其他系统可读取文件链接计数。
3. **初始化。** 实际创建缺少的目录，使七个叶目录均可访问。新项目创建根 README，写入标题“项目目录指南”和下表；已有 README 则按上一步的结果在末尾补充，保留原文字节、编码、BOM 和换行风格。既有说明全部有效时即使本次新建了目录也不改 README。只生成资料目录与根 README；不生成占位文件、阶段文档、业务代码或 CI，不运行上传、提交、部署等操作。
4. **检查结果。** 核对七个路径均为真实目录、指南实际覆盖全部七项。简要告诉用户新增了哪些、哪些已复用、指南在哪里；重复执行没有变化时如实说明。中途失败时记录已完成部分和受阻位置，不把计划当成完成，也不要删除用户文件。

## 项目目录指南

以下路径都相对于用户项目的根目录。已有原件可以保留在原位置，无需为符合这张表而搬动。

| 目录 | 什么时候用 | 典型内容 |
| --- | --- | --- |
| `docs/inputs/` | 收到尚未整理的资料时 | 访谈原稿、客户来稿、调研记录。 |
| `docs/requirements/` | 整理项目要解决的问题、功能范围和验收条件时 | 产品需求文档（PRD）、功能规格、验收条件。 |
| `docs/design/product/` | 设计用户如何完成任务时 | 用户流程、页面原型、交互与异常状态说明。 |
| `docs/design/technical/` | 确定功能如何实现时 | 架构设计、模块职责、接口契约、数据模型。 |
| `docs/development/` | 安排或记录开发工作时 | 实施计划、任务拆解、变更记录；不放业务源码。 |
| `docs/verification/` | 检查功能是否满足需求时 | 测试用例、实际测试结果、业务验收记录。 |
| `docs/delivery/` | 向使用方交付版本时 | 版本说明、使用手册、部署与交接记录。 |
