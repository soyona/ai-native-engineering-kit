# AI Native 工程规范

在 Codex 中打开项目文件夹，发送：

```text
请读取 https://github.com/soyona/ai-native-engineering-kit 的 README，按照其中的初始化指南，在当前目录初始化我的新项目。
```

## 多仓项目：一个入口，三个代码仓库

移动端、管理后台、服务端各用一个独立 Git 仓库。从三者中指定一个兼任**项目入口**，不必建第四个仓库。例如选服务端仓库为入口：

| 仓库 | 维护内容 |
| --- | --- |
| 移动端 | 客户端源码、端侧设计、测试、构建与发版说明 |
| 管理后台 | 管理界面、前端权限交互、测试与部署说明 |
| 服务端（兼项目入口） | API、数据、服务端测试与部署；另维护项目级文档和三仓清单 |

**入口 README** 列出三个仓库的名称、地址、职责和共享 API 契约位置。整体需求、跨端流程、总体架构、联调验收和发布记录只在入口仓维护；联合发布记录标明三仓各自的版本。**各代码仓 README** 写明本仓职责、项目入口和契约位置。契约原件只存一处，默认在服务端；移动端与管理后台引用它，不另存副本。未知地址标「待确认」，不猜链接。

分别在三个仓库中发送同一句提示词。首次可补一句「这是移动端仓库，项目入口在服务端仓库」。已知多仓但无法判断当前角色或入口归属时，先确认再写入。不要在父目录一次初始化三个子仓；不创建、克隆或修改其他仓库。

## 当前仓库的目录结构

**单仓项目、兼任入口的代码仓：** 无标记项默认创建，`*` 按本仓技术栈和用途启用。**其他代码仓：** 只建本仓需要的工程和资料目录，不重复生成七类项目级目录。已有文件一律保留。

```text
项目根目录/
├── README.md                   项目目录指南
├── docs/
│   ├── inputs/                 原始资料：访谈、客户来稿、调研记录
│   ├── requirements/           需求：范围、PRD、验收条件
│   │   └── features/ *         单项功能规格
│   ├── design/
│   │   ├── product/            产品设计：流程、交互、权限
│   │   │   └── prototypes/ *   原型与设计稿
│   │   └── technical/          技术设计：架构、接口、数据模型
│   │       └── decisions/ *    技术取舍及其依据
│   ├── development/            开发计划、任务拆解、变更记录
│   ├── verification/           测试结果、缺陷与验收记录
│   └── delivery/               版本说明、使用手册、交接记录
├── scripts/                    环境准备、校验、构建脚本
├── src/ *                      单应用源码
├── tests/ *                    可执行测试与样本
├── config/ *                   可共享的配置示例，不放密钥
├── apps/<应用名>/ *            多应用同仓，各自组织源码与测试
├── packages/ *                 应用间共享的代码
├── contracts/ *                跨端共用的 API、事件等机器可读契约
├── db/migrations/ *            数据库迁移
├── db/seeds/ *                 开发与测试种子数据
├── deploy/ *                   部署配置
├── infra/ *                    基础设施代码
├── .github/workflows/ *        GitHub Actions 工作流
└── .agents/skills/ *           项目专属 Codex 工作流程
```

**布局优先级：已有路径 → 框架约定 → 通用布局。** 普通单应用用 `src/`、`tests/`、`config/`；Java Maven 用 `src/main/java/`、`src/main/resources/`、`src/test/java/`。`apps/` 仅用于同一仓库内的多个应用，不用于容纳三个独立仓库。已有 `frontend/`、`backend/` 就地复用。`AGENTS.md`、`.gitignore` 保留，不自动生成。

## 初始化指南（给 Codex）

1. **选目录。** 只处理当前仓库。依据用户说明、本仓 README、已有结构和构建清单确认角色、套用上表和目录树。未声明多仓的空项目仍按单仓初始化；示例名称和可选目录不作为启用依据。来源无法确认时停止。
2. **先检查。** 写入前检查目标路径、父目录和根 README。遇到越界、文件占位、符号链接、目录联接或其他重解析点，停止并报告。补写已有 README 前须确认编码、BOM 和换行风格，并核实硬链接数为 1；无法确认或说明冲突时不写入。
3. **建目录，写指南。** 复用已有目录，不搬动原件。根 README 分「已经创建或复用」和「按需启用」，写明实际路径、用途及启用条件。保留原文和格式，只补缺项；已启用的条目不再列为待启用。除根 README 外不生成文件，不提交、不上传。
4. **核对结果。** 逐项核对实际目录与指南，报告新增、复用或受阻的路径。重复执行应无变化；中途失败保留现场，不删除用户文件。
